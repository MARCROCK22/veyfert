# Languages

`veyfert.Langs[T]` maps locales to a struct of your texts. The struct is yours, so every text is a
typed field, and a language that forgets one does not compile when the fields are `@[required]`.
The same struct translates commands for Discord.

```v
import os
import veyfert

// Texts are the bot's texts. Functions take values, such as a name.
struct Texts {
	greet fn (name string) string @[required]
	hello veyfert.CommandText     @[required] // the /hello command itself
}

const english = Texts{
	greet: fn (name string) string {
		return 'Hello, ${name}!'
	}
	hello: veyfert.CommandText{
		description: 'Says hello'
	}
}

const spanish = Texts{
	greet: fn (name string) string {
		return '¡Hola, ${name}!'
	}
	hello: veyfert.CommandText{
		name:        'hola'
		description: 'Saluda'
		options:     {
			'loud': veyfert.CommandText{
				name:        'fuerte'
				description: 'En mayúsculas'
			}
		}
	}
}

@[veyfert.Declare(name: 'hello', description: 'Says hello')]
@[veyfert.Locale('hello')]
struct Hello {
	langs &veyfert.Langs[Texts] // a dependency: it travels with every copy
mut:
	loud ?bool @[veyfert.Desc: 'In capitals']
}

fn (h Hello) run(mut ctx veyfert.CommandContext) ! {
	t := h.langs.of(ctx.interaction) // the user's language
	text := t.greet(ctx.author().username)
	ctx.write(content: if h.loud or { false } { text.to_upper() } else { text })!
}

fn main() {
	mut langs := &veyfert.Langs[Texts]{}
	langs.add('en-US', english)
	langs.add('es-ES', spanish)
	langs.alias('es-419', 'es-ES') // Latin American Spanish uses the Spanish texts
	mut bot := veyfert.new_client(token: os.getenv('DISCORD_TOKEN'))
	bot.commands.add(Hello{
		langs: langs
	})
	bot.commands.localize(*langs) // after adding the commands, before uploading them
	bot.upload_commands()!
	bot.run()!
}
```

## Picking a language

- `langs.get(locale)` returns the texts of `locale`, or of its alias, or of its language (`es`
  for `es-MX`), or of `langs.fallback` (`en-US` by default).
- `langs.of(ctx.interaction)` picks the language of whoever triggered the interaction. With
  `langs.prefer_guild_locale = true` it prefers the server's language.
- `langs.alias('es-419', 'es-ES')` makes one locale use another's texts.

Locales are Discord's: `en-US`, `es-ES`, `pt-BR`, `ja`… `api.available_locales_enum_*` in
[rest-api.md](rest-api.md#enums) lists them all.

## Translating commands

`@[veyfert.Locale('field')]` on a command names the `veyfert.CommandText` field of your struct that
translates it, and `bot.commands.localize(langs)` adds the translations to every such command:

| `CommandText` field | Translates |
|---|---|
| `name` | The command's name (Discord's rules apply: lowercase, no spaces) |
| `description` | Its description |
| `options` | Its options and subcommands, by their English name, each a `CommandText` |
| `choices` | The labels of an enum option's values, by value |

An empty field keeps the English text. Call `localize` after `commands.add` and before
`upload_commands`.

## Texts as constants

A struct with function fields can be a `const`, so each language can live in a file of its own:
`en.v` with `const english = Texts{...}`, `es.v` with `const spanish = Texts{...}`.
